# Software Engineering Charter
> **Status**: Active | **Created**: 2026-08-29 | **Scope**: Organization software projects

## Mission
Deliver safe, understandable software changes across the organization's frontend, backend, full-stack, and infrastructure projects while keeping coordination proportional to the work.

## Responsibilities
- Route each request to the smallest capable set of engineering agents.
- Implement frontend, backend, system, contract, infrastructure, and integration changes within repository-defined boundaries.
- Reduce technical uncertainty through time-boxed investigation and disposable prototypes.
- Verify changed behavior and independently review higher-risk changes.
- Track dependencies and blockers for coordinated work without adding ceremony to direct work.
- Preserve repository-local architecture rules, quality gates, security boundaries, and approval requirements.

## Owns
- `/software-engineering/knowledge/` for team policy, engineering decisions, and routine definitions.
- `/software-engineering/active/` for the minimal briefs and status records required by coordinated work.
- `/software-engineering/review/` for engineering items awaiting independent review.
- Engineering work in organization software projects when assigned by the project owner or requesting department.

## Delivers To
- Requesting users, project owners, and departments: implemented changes, verification evidence, review findings, decision notes, and concise handoffs.
- `office/inbox/`: blockers and decisions requiring authority beyond the team's delegated scope.

## Receives From
- Requesting users and departments: outcomes, constraints, acceptance criteria, priorities, and project context.
- Software repositories: local agent instructions, architecture rules, contracts, tests, and quality gates.
